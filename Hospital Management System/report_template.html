1. Executive Summary

The Hospital / Clinic Management System is a fullstack web application designed as an intuitive, fast, and accessible operational demo for outpatient clinics and medical practices. The system provides essential clinical workflows: registering and maintaining patient demographic records, managing the directory of practicing medical specialists, and booking and rescheduling clinical appointments with attending physicians.

The system is specifically engineered to bridge modern fullstack .NET development with industry-standard relational database management via Microsoft SQL Server and SQL Server Management Studio (SSMS). It demonstrates proper relational foreign keys, cascade constraints, parameterized query execution, high-performance object mapping via Dapper, and dynamic responsive client-side UI rendering with Bootstrap 5.3.

Key Highlight: The solution features an intelligent automatic database initializer. Upon starting the application with dotnet run, it detects the local SQL Server instance, creates clinic_db if absent, provisions all tables, and populates realistic demo seed data automatically without requiring manual intervention.

3. Relational Database Design (clinic_db)

The schema consists of three normalized core tables: patients, doctors, and the junction relationship table appointments.

3.1 Database Schema Definition

-- Database Definition (SSMS Compatible)
CREATE DATABASE clinic_db;
GO
USE clinic_db;
GO

CREATE TABLE patients (
    id INT PRIMARY KEY IDENTITY(1,1),
    name VARCHAR(100) NOT NULL,
    age INT,
    gender VARCHAR(20),
    phone VARCHAR(15)
);

CREATE TABLE doctors (
    id INT PRIMARY KEY IDENTITY(1,1),
    name VARCHAR(100) NOT NULL,
    specialization VARCHAR(100),
    phone VARCHAR(15)
);

CREATE TABLE appointments (
    id INT PRIMARY KEY IDENTITY(1,1),
    patient_id INT NOT NULL,
    doctor_id INT NOT NULL,
    appointment_date DATETIME NOT NULL,
    reason VARCHAR(255),
    FOREIGN KEY (patient_id) REFERENCES patients(id) ON DELETE CASCADE,
    FOREIGN KEY (doctor_id) REFERENCES doctors(id) ON DELETE CASCADE
);

3.2 Relational SQL JOIN Query

The primary appointment schedule report is produced by performing an inner join connecting appointments with the patient identity and doctor specialization: 

SELECT
    appointments.id,
    patients.name AS patient,
    doctors.name AS doctor,
    doctors.specialization,
    appointments.appointment_date,
    appointments.reason
FROM appointments
JOIN patients
    ON appointments.patient_id = patients.id
JOIN doctors
    ON appointments.doctor_id = doctors.id
ORDER BY appointments.appointment_date ASC;

5. RESTful API Specifications

HTTP Method Route Endpoint Function & SQL Query Description
GET /api/dashboard/stats Calculates aggregate counts and returns top 5 upcoming appointments.
GET /api/patients SELECT * FROM patients ORDER BY id DESC;
POST /api/patients INSERT INTO patients ... OUTPUT INSERTED.id VALUES (...)
PUT /api/patients/{id} UPDATE patients SET name=@Name ... WHERE id=@Id;
DELETE /api/patients/{id} DELETE FROM patients WHERE id=@id; (Cascades appointments)
GET /api/doctors SELECT * FROM doctors ORDER BY id DESC;
POST /api/doctors INSERT INTO doctors ... OUTPUT INSERTED.id VALUES (...)
PUT /api/doctors/{id} UPDATE doctors SET name=@Name ... WHERE id=@Id;
DELETE /api/doctors/{id} DELETE FROM doctors WHERE id=@id; (Cascades appointments)
GET /api/appointments Executes relational SQL JOIN between appointments, patients, and doctors.
POST /api/appointments INSERT INTO appointments ... OUTPUT INSERTED.id VALUES (...)
PUT /api/appointments/{id} UPDATE appointments SET appointment_date=@Date ... WHERE id=@Id;
DELETE /api/appointments/{id} DELETE FROM appointments WHERE id=@id;

6. Local Deployment & Execution Guide

6.1 Prerequisites

  • .NET 10 SDK (or .NET 8 / 9) installed.
  • Microsoft SQL Server (Express edition or LocalDB) running locally on localhost\SQLEXPRESS.
  • SQL Server Management Studio (SSMS) (Optional for visual management).

6.2 Execution Procedure

  1. Open a terminal in the project directory: cd e:\P1
  2. Start the server: 
    dotnet run
  3. Open any modern browser and navigate to: 
    http://localhost:5000
